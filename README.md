# 积分枢纽 PointHub

多平台 AI Agent 账号的**每日积分自动签到**、**积分看板**与**双端互通**工具。
Windows 桌面端 + Android 手机端，数据只在本机。

> **仅用于管理你本人合法持有的账号。** 本项目调用的是各平台的非公开接口，
> 可能违反平台服务条款、可能因平台改版失效、可能导致账号异常。
> 使用前请自行判断，风险自担。本项目与任何平台官方无隶属或合作关系。

| 每日自动签到 | 已实机验证 | 待实测 | 端点待补（见下） |

| 长效令牌自动续期 | 已实机验证 | 不支持 | 不支持 |

| 多账号 | 支持 | 支持 | 支持 |

界面上不会给你一个点了就报错的按钮。

## 加账号

账号页三种导入方式：

- **浏览器授权（推荐）**：点一下，会在你**平时用的浏览器**里新开一个标签页；
  登录并点「授权」，软件这边自动导入，并立刻读一次余额确认令牌真能用。
  拿到的是官方插件令牌（长效、能自动续期），不读取你浏览器的任何数据。
- **本机导入（Windows）**：直接读本机已登录的 WorkBuddy 客户端登录态，
  只读、不改客户端文件；导入前会联网验证一次余额，验证不过不落库。
  同一个账号重复导入只会更新那条记录，不会出现两条。
- **手动令牌**：从客户端或网页复制令牌粘进来，授权流程走不通时兜底。

**同一账号只会存在一条**：软件按平台用户 id（令牌里的 JWT `sub`）识别账号，
不管用哪种方式重复导入，都只更新已有记录；以前留下的重复记录会在下次导入时自动合并。
Trae / Qoder 的普通令牌无法解析身份，只能靠「整串令牌相同」识别。

浏览器授权和本机导入目前都只接了 WorkBuddy；Trae CN / Qoder CN 请用手动令牌（界面会提示）。

### 手机上也能用（Android App）

装 `积分枢纽PointHub_v<版本>.apk` 后，设置页「连接方式」里有两种运行模式：

- **本机模式**：账号导入、签到、历史都在手机上，自己管自己；
- **连接电脑**：手机只做遥控器——看电脑上的账号与积分、请求电脑代签；
  凭据始终留在电脑，不跨设备（见 `DECISIONS.md` D15）。

连接电脑的步骤：

1. 电脑端「设置 → 手机访问」：打开「局域网访问」，记下**访问地址**和 **6 位配对码**；
2. 手机和电脑连**同一个 Wi-Fi**；
3. 手机 App「设置 → 连接方式」选「连接电脑」，填地址（如 `192.168.1.5:47821`）
   和配对码，点「连接电脑」；
4. 配对成功后手机记住这台电脑，下次打开自动连上，不用再输码。

配对码 5 分钟一换、用一次就作废；关掉「允许手机签到」后手机只能看账本。
服务只认内网来源，公网地址连不上。

不想装 App 时，手机浏览器直接打开「访问地址」、输配对码也能看账本、点签到。

## 检查更新

设置页「更新」面板：

- **启动时自动检查**（可关）：发现新版本只弹系统通知，不自动安装；
- **检查 → 下载**：Windows 下载 `_Setup.exe` 后自动打开安装向导；
  安卓跳到浏览器下载 APK，下载完点开安装（系统会问是否允许安装未知应用）；
- **手动下载**入口始终可用，直接打开 GitHub Releases 页面；
- 国内直连 GitHub 慢时，来源切到「镜像」并填前缀（如 `https://ghfast.top/`），
  查询版本和下载安装包都会套用这个前缀。

自动更新不做静默替换：装不装、什么时候装，由你决定。

#### 手机连不上电脑？

按顺序排查，基本都在这几条里：

1. **同一 Wi-Fi**——手机没连 Wi-Fi，或连的是访客网络、与电脑不在同一网段，都连不上；
2. **地址填对**——要带端口，形如 `192.168.1.5:47821`（`http://` 可省）；
3. **配对码过期**——超过 5 分钟或已经用过，回电脑上看新码；
4. **防火墙**——Windows 第一次会弹「是否允许访问网络」，要选「专用网络」允许；
5. **Android 17 本地网络保护**——系统会拦截应用访问局域网。本项目构建时已把
   `targetSdk` 固定为 36（见 `scripts/patch-android-gradle.ps1`），装官方产物直接可用；
   若你自己重新出包，别把 targetSdk 改回 37，否则表现是「一直转圈最后超时」，
   而不是弹出权限提示。

### Qoder CN 的现状（重要）

Qoder 每日 100 Credits 自 **2026-11-19 10:00** 起只对付费/试用/会员卡账号开放，
体验版（免费）账号的入口被服务端直接隐藏。本程序把这种情况标为「无活动资格」，
不重试、不报错、不计入失败。

## 跑起来（Windows）

需要：**Rust 1.80+**、**Node 18+**、Windows 10/11（自带 WebView2）。

### 只想验收、还不打包：双击 `1. 一键启动预览.bat`

项目根目录下的 `1. 一键启动预览.bat` 用**当前源码**启动，不产出、也不改动 `dist/`。

它会先比对文件时间：**没改动的部分直接跳过编译**——什么都没改时是秒开；
改了界面才跑前端构建（约 2 秒），改了 Rust 才编译（约 22 秒）。

它的黑窗口是日志窗口，**关掉窗口 = 退出程序**。

### 想自己敲命令

```bash
# 1) 只跑命令行内核（不用装前端依赖，最快验证链路）
cargo run -p phctl -- doctor

# 2) 跑桌面端（开发模式，前端热更新）
cd apps/desktop/ui && npm install
cd ../src-tauri && npx @tauri-apps/cli dev
```

### 打包

```powershell
# 便携 exe（日常只要这个）
powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1

# 便携 exe + 安装包（特殊要求时才用）
powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1 -Installer
```

产物在 `dist/`，命名格式 `积分枢纽PointHub_v<版本>.exe`；安卓包见 `docs/ANDROID.md`
（targetSdk 固定 36，绕开 Android 17 本地网络保护）。

**`dist/` 里的文件视为已交付的历史版本，脚本不覆盖、不删除。** 要再出一版，
先按语义化版本升 `Cargo.toml` 里 `[workspace.package] version`，再跑脚本；
版本号没变会直接报错退出——逼你先想清楚这次该升哪一位。

**实测（本机 Windows 11 / WebView2 158）**

| 指标 | 数值 |
|---|---|
| 便携 exe 体积 | 4.6 MB（单文件，无外部资源） |
| 空闲内存 | 约 78 MB |
| 冷启动到可见界面 | 1 秒内 |

## 命令行（phctl）

界面出问题的时候，先用它把「是不是软件的错」分清楚。

```bash
phctl doctor                                  # 环境自检 + 平台能力矩阵
phctl account add --vendor workbuddy --label 主号 --refresh-token <令牌>
phctl account list
phctl status                                  # 查积分与今日签到状态
phctl checkin                                 # 一键全部签到
phctl travel --id 主号                         # 派猫猫旅行
phctl plan                                    # 每个账号下次执行时间
```

`phctl` 与桌面端**共用同一个数据目录**（默认 `%LOCALAPPDATA%\PointHub`），
所以两边看到的是同一份账号。

## 数据与安全

| 项目 | 位置 / 做法 |
|---|---|
| 数据目录 | 默认 `%LOCALAPPDATA%\PointHub`，可在设置里改（搬迁会复制现有数据） |
| 令牌 | 只存在 `vault.bin`；Windows 用 DPAPI 加密，安卓用 AES 回退后端；换机后需重新导入 |
| 账号元数据 | `accounts.json`（**不含令牌**） |
| 积分历史 | `history.jsonl`（追加写，一行一条快照） |
| 日志 | `logs/YYYY-MM-DD.log`（不含令牌明文） |

程序不会把任何凭据发到网络上除平台官方域名以外的地方。
