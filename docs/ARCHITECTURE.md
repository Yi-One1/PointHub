# 架构

## 分层

```
┌──────────────────────────────────────────────────────────┐
│ 界面层   apps/desktop/ui (React + TS)                     │
│         总览 / 账号 / 设置 / 悬浮球                         │
└───────────────────────┬──────────────────────────────────┘
                        │ invoke（只调用命令，不碰业务）
┌───────────────────────▼──────────────────────────────────┐
│ 外壳层   apps/desktop/src-tauri (Rust)                    │
│         窗口 / 托盘 / 通知 / 自启 / 悬浮球 / 命令接线        │
└───────────────────────┬──────────────────────────────────┘
┌───────────────────────▼──────────────────────────────────┐
│ 编排层   crates/ph-engine                                 │
│         取凭据 → 刷新令牌 → 调平台 → 回写 → 复核 → 记账      │
└──────┬──────────────┬──────────────┬─────────────────────┘
       │              │              │
┌──────▼─────┐ ┌──────▼──────┐ ┌─────▼──────────────────────┐
│ ph-vault   │ │ ph-store    │ │ ph-providers               │
│ 凭据加密   │ │ 明文数据     │ │ workbuddy / trae / qoder    │
└──────┬─────┘ └──────┬──────┘ └─────┬──────────────────────┘
       └──────────────┴──────────────┘
┌──────────────────────────────────────────────────────────┐
│ 领域层   crates/ph-core                                   │
│         模型 / 错误 / 调度 / 设置（无 IO、无网络）           │
└──────────────────────────────────────────────────────────┘
```

**依赖方向只准向下。** `ph-core` 不 import 上层；`ph-providers` 不认识数据库；
界面层不认识 HTTP。

> 例外说明：`ph-core` 依赖 `reqwest` 仅为把 `reqwest::Error` 映射成 `Error::Network`，
> 自身不发起任何请求。这是刻意的取舍——否则每个适配器都要重复写一遍 `.map_err`。

## 一次签到的完整链路

```
1. 从 vault 取凭据（内存里只有这一份明文）
2. 有长效令牌 → 换 access_token；顺便把轮换后的长效令牌回写
3. 调平台 /daily-checkin
4. 无论成败，把可能被轮换的凭据写回 vault
5. 再查一次状态 → 生成快照（验证「领到了」是否真到账）
6. 追加快照到 history.jsonl，更新账号的 last_checkin_at / last_error
7. 发系统通知（按设置）
```

第 4 步不能省：令牌轮换是「一次性」的，回写失败就等于把这个账号的钥匙丢了。
第 5 步也不能省：接口返回成功不等于积分到账，必须复核。

## 关键取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 数据库 | JSON + JSONL，不用 SQLite | 账号量级是十位数；省掉 C 依赖与几 MB 体积；追加写天然抗断电 |
| 加密 | 系统级（DPAPI），不引入自定义 KDF | 密钥不落盘，程序不保管秘密 |
| 并发 | 签到串行 + 随机间隔 | 上游有风控；并发带来的收益远小于封号风险 |
| 定时 | 应用内循环，不用 Windows 计划任务 | 计划任务要提权、卸载易残留、用户看不见 |
| 悬浮球 | 独立窗口，不复用主窗口 | 透明/置顶/无边框窗口与主窗口的系统行为完全不同 |

## 数据流约束

- **令牌永不进日志**：`Credential` 的 `Debug` 手写成脱敏版；日志只写账号别名。
- **快照只追加**：历史是事实记录，不提供「改历史」的接口。
- **失败要留痕**：`last_error` 保存人话，方便用户截图反馈。
