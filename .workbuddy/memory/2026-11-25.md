# 2026-11-25

## 积分枢纽 PointHub v0.1.0 骨架落地

**背景**：用户要做多平台 AI Agent（WorkBuddy / Trae CN / Qoder CN）每日积分自动签到工具，
双端（Windows + Android），要求体积小、可频繁迭代、凭据留本机。仓库 github.com/Yi-One1/PointHub。

**开工前定了 12 个决策**（三轮提问，全部记录在 `DECISIONS.md` D01–D12）：
- 技术栈：Rust 共享核心 + Tauri 2 双端 + 一套 React UI（否掉 Flutter/Compose 双 UI/Python）
- 互通：局域网直连，PC 当服务端，不经云
- 多账号：长效令牌导入为主（不做客户端换号抓取）
- 令牌：DPAPI 系统级加密，不设主密码
- 签到时间：按平台刷新时刻设默认（WB 00:10 / Trae 00:10 / Qoder 10:10）+ 确定性抖动
- 首版范围：WorkBuddy 打穿，Trae/Qoder 同版跟上
- 更新：GitHub Releases 起步，源地址可配置
- 打包：命名 `积分枢纽PointHub_v<版本>.exe`，日常只出便携 exe
- 卸载：默认删干净，可选保留数据
- 协议：MIT

**已实现**：6 个 Rust crate（core/vault/store/providers/engine/cli）+ Tauri 外壳 + React 三页界面 + 悬浮球。
- 发布版实测 **4.5MB**，空闲内存 ~78MB（比预估的 8–15MB 还好，因为前端产物仅 166KB）
- `cargo test --workspace` 21 个测试通过
- WorkBuddy 链路按官方接口完整实现（含令牌轮换回写、派猫猫旅行状态机）
- Trae CN / Qoder CN 适配器已写，但标 `verified: false`，界面显示「待实测」

**关键事实（下次别再查）**：
- WorkBuddy 签到域名以凭据里的 `domain` 为准（写 `copilot.tencent.com` 会 404）；旅行域名是 `www.workbuddy.cn` 且路径无 `/v2`；余额字段是复数 `total_credits`
- WorkBuddy 长效令牌刷新：`POST copilot.tencent.com/v2/plugin/auth/token/refresh`，头 `X-Refresh-Token` / `X-Auth-Refresh-Source: plugin` / `X-Domain`，**每次返回新令牌必须回写**
- Qoder 自 2026-11-19 10:00 起每日 100 Credits 只对付费/试用账号开放，免费号入口被服务端隐藏 → 必须映射成 `NotEligible` 而不是失败
- Trae 需真机 `x-device-id` + `X-User-Region: CN`，设备不一致返回 9074；令牌刷新需设备私钥签名（未实现）
- 参考仓库协议：Trae-workbuddyAssistant = MIT 可用；CheckinBox-Tools 与 workbuddy-signin **无 LICENSE** → 只能借鉴接口事实，不复制代码

**环境缺口**：本机无 JDK、无 Android SDK/NDK → 安卓端无法编译。装环境前必须先问用户。

**下一步**：常驻调度器 → 真实账号联调 → 局域网互通 → Android → 自动更新/卸载清理。
