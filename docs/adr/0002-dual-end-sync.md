# ADR-0002：双端同步同步账号与历史，凭据不跨设备，每账号唯一执行端

- 状态：已采纳
- 日期：2026-11-26
- 相关：`DECISIONS.md` D15；调整 D03

## 背景

需求要求 Windows 与 Android 双端互通，且安卓端既能连接 PC，也能管理本机账号。

「双向同步」有歧义：同步的是账号元数据？积分历史？凭据？还是操作权？
其中凭据最危险。WorkBuddy 的 refresh token **每次刷新都会轮换**，旧令牌立即失效：

```
PC 持有 refresh-A ──签到──> 平台返回 refresh-B
手机仍持 refresh-A ──签到──> 401 / 令牌失效
```

如果两端各存一份同一账号的凭据并都去签到，必然互相把对方的钥匙刷废。

## 决策

1. **同步内容**：账号元数据（别名、开关、排期）、积分快照、签到历史、活动记录。
2. **不同步内容**：凭据（refresh token / access token / cookie / 设备标识）。
3. **唯一执行端**：每个账号同一时刻只能有一个执行端（PC 或手机）。
   执行端拥有凭据，负责签到；另一端只展示，并可请求执行端代为签到。
4. **身份合并**：优先使用平台返回的稳定用户 id；拿不到时按本地 id 同步，
   两端各导一次产生的两条记录由用户手动合并。**禁止按令牌片段自动合并**
   ——令牌会轮换，片段会变，误合并比重复更糟。

## 理由

- 凭据不搬家，就不存在「两台设备抢着刷新同一把钥匙」的失效窗口。
- 账号和历史不含秘密，同步失败最多是数据旧一点，不会让账号掉登录。
- 唯一执行端把「谁去签到」变成显式状态，界面能直接回答，而不是靠运气。

## 代价

- 手机看不到 PC 账号的凭据，不能直接为 PC 账号签到，只能请求 PC 执行。
- 换执行端需要手动迁移，且迁移后旧端必须停用。
- 需要在现有 6 位配对码之上增加**持久设备配对**，否则每次启动都要重新配。

## 替代方案与被否原因

| 方案 | 否掉的原因 |
|---|---|
| 凭据也同步、两端都能签 | 令牌轮换冲突，必然出现「一端签到、另一端掉登录」 |
| 只做浏览器访问，不做 App 互通 | 不满足需求 4 对安卓端的要求 |
| 账号与积分上云 | 违背凭据留本机、体积小、无第三方服务器的既有边界 |

## 何时该重新审视

- 若平台改为「一个账号可签发多个互不影响的长期凭据」，可重新评估凭据同步。
- 若安卓端必须脱离 PC 独立完成全部平台签到，执行端模型需要升级为多设备协调。
